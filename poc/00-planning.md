## 1. 점수 체계

### 척도

- 사진 점수, 리뷰 점수, 최종 점수 모두 **0~10점** (소수점 1자리 허용, 예: 7.5)

### 최종 점수 계산식

```
최종 점수 = 사진 점수 × w_photo + 리뷰 점수 × w_review
(w_photo + w_review = 1)
```

- **가중치는 UI에서 조정 가능**하게 설계한다.
- 기본값: `w_photo = 0.5`, `w_review = 0.5`

### 점수 산출 주체

- 사진 점수: 내부 사진을 비전 모델(OpenAI)로 분석 → 조명/좌석 배치/공간감 기준
- 리뷰 점수: 최신 리뷰를 LLM으로 분석 → 긍정/부정 표현 종합
- 각 점수는 **판단 근거(텍스트)** 를 함께 산출해 리포트에 기록

---

## 2. 탐색 범위

- **분석 방식: 순차 처리.** 여러 장소를 병렬로 분석하지 않는다. (약관/봇 차단 리스크 최소화)
- **1회 실행당 최대 분석 장소 수: 기본 30개.** 설정으로 조정 가능.
- 후보 목록은 역/지역 기준으로 확보하되, 한 개씩 순서대로 분석한다.
- 필터로 제외된 장소는 심층 분석하지 않지만 리포트에 제외 사유와 함께 기록한다.

---

## 3. 약관 / 봇 차단 리스크 대응

- **요청 간 딜레이**: 장소 분석 사이에 대기 시간을 둔다. (랜덤 지터 권장)
- **속도 제한(rate limit)**: 단위 시간당 요청 수를 제한해 인간에 가까운 탐색 속도 유지.
- 병렬 분석 금지(2번 항목)와 함께 적용해 과도한 트래픽을 방지한다.

---

## 4. 실시간 진행 화면

- **CDP 영상 스트리밍**으로 구현한다.
- 브라우저 탐색 화면을 프론트에 실시간 중계하고, 에이전트의 판단 로그와 리포트 갱신을 함께 노출한다.

---

## 5. 사용자 설정 항목 (초안)

향후 UI/스키마 설계의 기준. 값은 예시.

```yaml
# 탐색 조건
search:
  location: "강남역"          # 기준 역/지역
  max_places: 30              # 1회 최대 분석 장소 수 (조정 가능)

# 사전 필터링 조건
filters:
  categories: ["양식", "일식"]
  min_review_count: 50
  max_distance_m: 700         # 기준 역으로부터 반경(m)

# 점수 가중치 (합 = 1.0)
weights:
  photo: 0.5
  review: 0.5

# 점수 기준 (프롬프트에 반영)
scoring:
  photo: "어둡고 차분한 분위기, 넓은 좌석 간격, 대화하기 좋은 구조"
  review: "깔끔함, 조용함, 대화하기 좋음 등 긍정 표현"

# 리스크 대응
throttle:
  delay_ms: [2000, 5000]      # 요청 간 랜덤 딜레이 범위
  rate_limit_per_min: 10      # 분당 최대 요청 수
```

## 확정 요약

| 항목 | 결정 |
|------|------|
| 점수 척도 | 0~10점 |
| 최종 점수 | 사진 × w + 리뷰 × w (가중치 UI 조정, 기본 50:50) |
| 분석 방식 | 순차 처리 (병렬 금지) |
| 최대 장소 수 | 기본 30개 (설정 가능) |
| 리스크 대응 | 요청 간 딜레이 + 속도 제한 |
| 실시간 화면 | CDP 영상 스트리밍 |
